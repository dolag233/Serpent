fix(fbx): use ufbx_triangulate_face instead of the hand-written fan (Serpent-8pg6)

The bridge's fan triangulation rendered textures "fragmented" on complex
meshes: fans are wrong for concave polygons, which DCC meshes inevitably
contain. The original reason for avoiding ufbx_triangulate_face was a
buffer-size bug: ufbx.h says (n-2)*3-1 indices are needed, but the
implementation writes (n-2)*3 — allocating the smaller size overwrote
adjacent heap and made the output look corrupted in wasm32.

- bridge now calls ufbx_triangulate_face with the correct (n-2)*3 space
  (quads split along the shortest diagonal with crossing detection;
  ngons ear-clipped) — verified on the user model: 498k triangles,
  geometric-vs-vertex normal consistency flipped=0, badAngle 0.06%
- viewer loadFbx returns to the ufbx conversion primary path
  (FBXLoader stays the conversion-failure fallback)
- WASM rebuilt, lock hash updated (glue unchanged); fbx-conversion 20/20,
  model-viewer E2E FBX case passes
