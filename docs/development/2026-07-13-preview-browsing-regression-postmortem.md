# 缩略图与查看页面回归复盘（2026-07-13）

## 事故

用户在真实已有资源库中看到全部缩略图加载失败，双击查看也没有内容。此前自动测试显示通过，但没有覆盖“已有资源库 + 真实协议字节 + 媒体实际解码 + 完整用户旅程”。

## 根因链

1. 测试主要验证 Worker job、artifact 记录和 DOM 容器，未验证 Renderer 最终收到的媒体能被浏览器解码。
2. 自定义 `serpent://` 协议、Main、Worker、CSP、资源定位和 Renderer 被分层测试，却缺少穿透全部层的 Electron E2E。
3. 测试集中在新建资源库；已存在 artifact、旧 schema、重启后的资源定位路径覆盖不足。
4. 功能切片大量并行实现后，只汇总了各自的绿色结果，没有在最终共享工作树上运行完整主线门禁。
5. “预览生成 job 成功”被误当成“用户能看到预览”，验收指标选错层级。

## 修复

- 支持原生浏览器解码的图片/视频可以安全直读源文件，不再等待缩略图或代理 job。
- 缩略图使用等比 `contain`；支持预览但缺少衍生物时自动、幂等、高优先级调度。
- 查看页嵌入主界面中央；衍生物生成不阻塞打开；不支持格式只提供外部打开。
- 浏览区改为连续加载、平铺/瀑布流、统一滚动根和可调卡片尺寸。
- 默认忽略 `.DS_Store`、`Thumbs.db`、`desktop.ini`、`._*`、VCS 与依赖目录。

## 永久门禁

- 图片 E2E 必须断言 `complete && naturalWidth > 0`；视频必须至少 `readyState >= HAVE_METADATA` 且尺寸非零。
- 核心媒体 E2E 必须穿透 Renderer → Preload → Main → Worker → 文件系统/SQLite → `serpent://` → Chromium 解码。
- 必须分别覆盖新导入、已有资源库重开、完整进程重启、打包产物和真实二进制冒烟。
- 任何媒体协议、CSP、路径解析、打包或进程边界改动都触发该门禁。
- 多 agent 合流后只认可最终工作树的 `npm run verify:mainline`，不以子任务历史绿色结果替代。

## 本轮新增证据

- 真实 PNG 缩略图与客户端查看解码 E2E。
- 不支持格式无“重试生成”误导入口。
- 73 项资产无分页连续浏览。
- 瀑布流首尾完整可达。
- 普通滚轮不缩放；Ctrl+Wheel/pinch 缩放并保留视野锚点资产。
- 完整退出后自动重开最近资源库并选中、聚焦上次资产。
