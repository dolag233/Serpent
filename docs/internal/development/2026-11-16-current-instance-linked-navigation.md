# 当前旧版实例的万级链接库卡顿诊断

工单 Serpent-jpxsz。用户报告同步万级文件后界面卡顿，创建文件夹约一分钟才出现，切换慢。保留用户进程与既有 RAW 修复；没有修改真实资源库、安装目录或源文件。

## 现场

- 读取当前运行进程对应安装包内 package.json，确认安装版本为 **0.3.2**；当前库 user_version 为 **59**，没有 linked_directory_snapshots 表。当前开发源码与已发布 v0.3.7 使用 v60，并已包含该目录索引。不能把旧实例当成当前源码的回归证据。
- 用户库只读统计约 14,563 条资产记录（含非当前可见状态），可见界面约 13,119 项；链接源树约 2,023 个目录、13,929 个文件。只读 os.walk 约 165ms，因此不能仅归因于磁盘吞吐。
- 同步相关日志包含 11,657 条链接资产路径对账记录，后台对账 owner 单次累计约 7.6–11.3 秒，导航摘要 owner 约 3.2 秒，以及 Worker 请求超时、原生媒体资源压力和冷却。owner 持续时间包含等待，不能全部等同 CPU 执行时间。
- 初次截图因窗口被遮挡显示了其他窗口；激活目标后看到了真实 Serpent。随后用户按 Escape 停止 Computer Use，工具要求终止该轮。用户明确要求不使用 Computer Use 继续后，仅用源码、日志、只读 SQL 与隔离测试，未再进行 UI 操作。
- 尝试已有 DevToolsActivePort 提供的环回端口被拒绝连接，该描述符已失效；未修改调试设置或重启实例。未访问凭据文件。

## 版本差异与已存在的优化

`git show v0.3.2:src/worker/library-service.ts` 的 listLinkedFolders 在导航读取中递归 collectLinkedDirectoryPrefixesFromDisk；创建完成后 UI 还要等待内容重新加载及整库导航摘要。当前实现已使用持久目录快照、按成员版本缓存的资产路径投影、分片/合并导航读取和后台调度安全点。用户原实例没有这些实现。

通过 GitHub CLI 核实 v0.3.7 已公开发布，且该 tag 源码包含 v60 目录快照；未下载安装器或替换用户应用。本轮不重复编写已发布的性能改动。

## 当前源码隔离测量

扩展已有 `tests/worker/linked-navigation-performance.test.ts`，在 150,000 条合成资产记录和 4,100 个空目录的元数据基准后，实际创建一个空目录并确认新的导航摘要包含其 folderId；增加创建和创建至摘要耗时。修正原测试依赖工作区预先存在 tmp 父目录的问题，改为工作区直接创建独立临时根，并由 finally 清理。

执行：`SERPENT_LINKED_NAV_BENCHMARK=1 node scripts/run-vitest-with-electron.mjs run tests/worker/linked-navigation-performance.test.ts --disableConsoleIntercept`。

| 指标 | 当次结果 |
| --- | --- |
| 并发两个冷导航请求（合并构建） | 309ms |
| 热导航 p50 / p95 | 均小于四舍五入到 1ms 的精度 |
| 最大事件循环间隙 | 31ms |
| 创建空目录 | 27ms |
| 创建开始至含新目录的导航摘要 | 71ms |
| 定向测试 | 1 passed |

首轮因 tmp 父目录不存在在夹具创建前失败；修正后执行通过，第一次通过的 console 被捕获，第二次显式关闭 console 捕获取得以上数值。夹具库、文件和目录由测试 finally 清理。没有把 150k 元数据夹具冒充正式 20k 混合媒体基线；本轮未运行该混合媒体基线，没有测试真实媒体缩略图吞吐或真实 UI 渲染延迟。以上结果与旧实例现场不是同一受控负载，不能计算为确定的提速倍数。
