## 当前最重要的工作方式

`docs/internal/qa/human-acceptance-checklist.md` 是唯一的人类功能验收队列，目前有 83 个独立 ID。下一位 agent 必须遵守：

- 新的用户可操作增量与实现放在同一提交中更新清单，不等会话结束再补。
- 阶段性和最终汇报列出新增或变化的验收 ID、用户操作步骤及仍不可验收的范围。
- 自动化、代码审查、Computer Use 或 agent 自测只能把条目推进到“待人类验收”；只有用户本人能标记“人类验收通过”。
- 用户报告问题时，当前回合立即记录“不通过”或“已撤回”，保留原反馈；修复后以新基线重新进入队列。
- 不用旧包、旧提交、未执行平台或仅有内部实现的工作证明当前功能完成。

详细事故复盘与约束见 `docs/internal/development/2026-07-14-acceptance-discipline-retrospective.md`。

## 安全与边界提醒

- Renderer 不接收任意绝对路径、SQL 或文件系统能力；数据库和资源文件操作只在 Library Worker。
- 所有跨进程协议继续使用 Zod 运行时验证。
- 所有用户可见错误必须给出具体、可操作原因并写日志，不得只显示“操作失败”。
- 不在 SMB/NAS 上运行 Electron，不复用跨平台 `node_modules`，不把任何密钥、用户路径样本或私人资源库内容写入仓库。
