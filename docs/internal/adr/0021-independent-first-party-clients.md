# ADR-0021：桌面与 CLI 采用独立进程并短暂协调资源库写入

- 状态：已接受
- 日期：2026-07-13
- 替代：ADR-0019 中“每台电脑只运行一个 Serpent 应用进程”的决定

## 一句话解释

桌面客户端和 CLI 不互相依赖，也不需要常驻核心服务；它们可以同时读取同一资源库，但任何会修改数据库或文件的操作都通过资源库级跨进程写锁短暂串行执行。

## 背景

Serpent 需要原生支持命令行操作，使人类、脚本和软件 agent 在桌面客户端未运行时也能使用绝大部分领域功能。CLI 若依赖正在运行的桌面应用或常驻 daemon，会增加安装、启动和故障恢复的隐式状态；CLI 若绕过领域层直接修改 SQLite 或文件，又会破坏数据库与文件操作的一致性。

原 ADR-0019 选择每台电脑单一应用进程，主要用于避免多个进程重复监听、迁移和调度任务。CLI 成为一等客户端后，该约束不再符合产品要求，需要以明确的跨进程协调取代单实例假设。

## 决策

- 桌面客户端与 CLI 是平等的一等客户端；二者都是独立可执行进程，不互相依赖，也不要求常驻 daemon。
- 每次 CLI 调用在自己的进程中启动同一套领域命令层和 Library Worker。CLI 不直接执行任意 SQL，也不绕过 Library Worker 操作资源库文件。
- 多个本机进程可以并发读取同一资源库。
- 任何修改数据库或资源库文件的命令，在实际写入前取得该资源库的跨进程写租约；同一资源库的修改操作在租约期间串行执行，完成或失败后立即释放。
- 写租约不是打开资源库期间持续持有的独占锁，也不是多机协作协议。锁被占用时，调用方等待至可配置超时，超时后返回带原因和日志关联信息的 `LIBRARY_BUSY` 错误。
- SQLite 事务继续保证数据库写入一致性；导入、移动、重命名、删除等跨数据库与文件系统的操作继续使用可恢复的 `file_operations` 阶段记录。写租约不能代替事务或崩溃恢复。
- 每个客户端都负责监控资源库文件与外部源文件变化。资源库另外维护单调递增的持久变更序号，使已打开客户端能够发现其他本机进程完成的数据库修改并刷新受影响内容。
- schema 迁移也属于修改操作，必须在写租约下执行。迁移失败不得留下可被其他进程继续写入的半迁移资源库。
- 后台任务由启动该任务的独立进程执行。以 detached 方式启动的 CLI 任务由独立的无界面 job 进程承载，不依赖发起终端或桌面客户端存活。
- 本决策只覆盖同一台电脑上的多进程使用；同一资源库的多机并发仍不受支持。

## 后果

- GUI、CLI、未来 MCP 适配器和测试必须共享领域命令实现与运行时校验，不能各自维护数据库写入逻辑。
- Library Worker 从“整台电脑唯一数据库所有者”调整为“单一客户端进程内的唯一数据库与文件操作所有者”。
- 需要实现可检测进程死亡并过期的写租约、等待超时、持久变更序号，以及多进程并发测试。
- 文件监控可能重复发现同一变化；刷新与索引逻辑必须可重复执行，并以资源库当前状态收敛。
- 后台任务调度必须防止两个进程领取同一个持久任务。
- 不引入守护进程，换来的代价是每次 CLI 调用需要承担启动 Library Worker 和打开资源库的成本。
