# ADR-0002：首版聚焦个人专业媒体资产库

- 状态：已接受
- 日期：2026-07-11

## 背景

完整愿景同时包含本地管理、集中存储、团队协作、版本管理、专业预览、AI 和插件。一次实现这些能力会使身份、同步、权限、冲突和存储问题互相绑定。

## 决策

MVP 聚焦 Windows 与 macOS 上的个人专业媒体资产管理，首发同时面向游戏美术、影视后期和平面/UI/品牌设计师，并支持这些人群共有的常见图片、视频及部分专业图像格式。

MVP 推迟团队协作、版本管理、3D 预览、PureRef 式白板、对外插件机制和创作软件集成。移动端不在长期计划中。

同一资源库在多台电脑上的并发使用属于协作与同步边界，不进入 MVP；MVP 只支持同一时间由一台电脑活动使用该资源库。

单个资源库按最多约 10 万个文件、2 TB 原始内容设计和验收。

三类首发用户共用“导入或链接 → 整理 → 搜索/过滤/排序 → 快速预览 → 外部打开”的 MVP 验收主线；行业专属制作流程不作为 MVP 验收条件。MVP 使用工作流和性能指标验收，不设置用户量、留存率等商业指标。

团队共享资源库、集中存储和客户端自动同步属于后续阶段；评论、审批等协作工作流不作为自动同步的前提。

本地模型、官方云、自托管、自动同步、可见版本管理和商业模式均明确留到 MVP 后分别设计，不作为当前发布阻塞项。

## 理由

当前最明确的问题是资产散落、检索慢和无法快速预览。个人资产库可以直接验证导入、索引、组织、搜索、预览和 AI 自动归类的价值。

## 后果

- MVP 可以在没有用户账号、权限系统和冲突解决的情况下运行。
- 数据模型仍需为未来的资源库身份、上传用户和同步状态留出演进空间。
- 核心内部仍应保留模块边界，但 MVP 不承诺稳定的第三方插件 API。
- 发布验收使用可重复的工作流场景和性能测试，不依赖遥测或商业采用率。
