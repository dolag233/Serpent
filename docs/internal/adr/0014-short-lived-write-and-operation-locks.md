# ADR-0014：不锁整个资源库，只短暂协调写入与文件操作

- 状态：部分由 ADR-0019 替代
- 日期：2026-07-11

## 一句话解释

打开资源库不等于占有资源库。只有真正修改数据库或移动、删除文件时，才短暂阻止别人同时改同一内容；操作完成立即释放。

## 背景

长期资源库锁会产生陈旧锁、强制解锁和同步工具传播锁文件等问题，也容易被误解为团队资产锁。MVP 尚不提供团队编辑与身份系统，并明确不支持同一资源库在多台电脑上并发使用。

## 决策

- 不创建长期锁住整个资源库的持久锁文件。
- 原决定允许多个独立 Serpent 进程同时打开同一资源库；该部分由 ADR-0019 替代为每台电脑单一应用进程。资源库本身仍不创建持久独占锁。
- 数据库写入使用短事务，由数据库在事务期间协调单写入者。
- 元数据实体使用版本号进行乐观并发校验；基于旧版本提交时不静默覆盖。
- 导入、移动、重命名和删除只临时占用相关文件或文件夹，并记录操作 ID、设备/进程、开始时间和阶段。
- 操作完成立即释放占用；崩溃恢复扫描未完成操作记录，能安全判断时自动继续或回滚，只有无法安全判断时才请求用户选择。
- MVP 不提供团队用户资产锁、checkout 或强制解锁。
- 操作系统或网络文件系统的底层锁只用于具体 I/O，不被视为可靠的跨设备协作协议。
- 若采用 SQLite，本地资源库可使用 WAL；检测为 NAS 时使用 rollback journal，并显示网络文件系统风险提示。

## 后果

- 文件操作必须设计成可恢复的多阶段流程，不能假设磁盘操作与数据库事务可以一次原子完成。
- 多机并发冲突 UI 不进入 MVP；未来团队版另行设计用户可理解的冲突与锁定交互。
- NAS 文件锁和同步刷盘的可靠性取决于具体网络文件系统，产品不能保证与本地磁盘相同的数据安全。
- 团队版将另行设计带用户身份、租约和服务端仲裁的资产锁，不复用本 MVP 机制冒充协作锁。
