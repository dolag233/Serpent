# ADR-0006：支持同时打开多个独立资源库

- 状态：已接受
- 日期：2026-07-11

## 背景

用户可能按个人素材、公司项目或客户拆分资产。原文件既可能复制进资源库，也可能留在任意磁盘目录中。

## 决策

用户可以创建多个相互独立的资源库，并同时打开。每个资源库是一个可整体移动的自包含磁盘目录，包括数据库、托管原文件和衍生预览。资源库文件夹的语义由 ADR-0013 定义。

多个已打开资源库之间不执行联合搜索，标签彼此独立。跨资源库拖放资产时复制资产，不从源库移除。

资源库允许位于本机磁盘、移动硬盘、NAS 或第三方同步目录。网络及同步目录存在一致性风险，产品提示风险但不禁止用户选择。资源库不持有长期独占锁；并发规则见 ADR-0014。

NAS 使用中断线时停止写入并进入只读/离线状态；恢复后重新校验资源库再允许写入。

资源库格式跨 Windows 与 macOS 可直接读取。链接文件夹保存的是设备路径，路径失效时由用户重新指定。

资源库文件夹的基数和物理映射由 ADR-0013 定义。

Label、描述、标签、评分、色卡和组织关系等用户元数据只保存在 Serpent 数据库中。MVP 不修改原文件内嵌元数据，也不在原文件旁创建 sidecar 文件。

Serpent 不创建自动数据库备份。用户通过备份整个自包含资源库目录保护托管资产、数据库和衍生数据；链接文件夹中的源内容需要单独备份。

## 理由

- 多资源库允许用户隔离不同项目、客户或使用场景。
- 数据库元数据避免污染原始素材目录，也能为复杂查询和原子更新提供一致存储。
- 标签负责多重分类，不复制资产内容。

## 后果

- 应用内部仍需使用事务、原子替换和安全关闭等机制，避免自身操作损坏数据库。
- 产品需要清楚提示“备份资源库”不包含链接文件夹的外部源文件。
- 资源库需要稳定身份和明确的数据目录。
- 同时打开多个资源库时，后台索引、预览和 AI 任务的资源调度仍需决定。
- NAS 与同步目录需要专门验证数据库模式、断线恢复和完整性校验。
- 资源库移动后可直接打开；失效的链接文件夹由用户重新指定路径。
- 若未来需要与其他工具交换元数据，应提供显式导入/导出，而不是依赖 sidecar。
