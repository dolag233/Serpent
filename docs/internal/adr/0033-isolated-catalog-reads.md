# ADR-0033：Library Worker 内的只读目录执行隔离

> 状态：2026-09-13 设计采用；实施与性能验收未完成。
> 细化 ADR-0018/0019 的进程实现；保持单一持久化 owner 和 Renderer/Main 权限边界。

现有 scheduler、网络快照和浏览查询共享执行线程；运行中的同步 SQL/网络文件调用不能被后到的高优先级 JS 消息打断。在 Library Worker 子系统中增加受控、可丢弃的只读目录执行器（独立 UtilityProcess），由 Main 直接路由经过校验的窄语义查询。Main 不打开 SQLite、不扫描资源库；只读执行器不得迁移、恢复、修改资源文件或执行 job。唯一持久化 owner 继续负责主库与资源文件的全部修改。

本地库读取同机只读连接；NAS 仅读取 owner 发布的本机不可变快照。只读执行器不直接访问远端 SQLite，不复制完整 LibraryService。过期慢读可以撤销进程并由有界预热执行器接管；写 owner 不适用该取消方法。代次撤销、连接释放和库关闭/删除次序由现有生命周期扩展管理。

未选择仅在原线程提高优先级，因为不能抢占已执行同步调用；未选择本地可写主库同步回NAS，因为改变持久化与冲突语义；未选择无限 worker 池，因为进程和句柄成本会随多库、多窗口放大。

代价是额外读进程、读版本契约和快照寿命管理。首个隔离里程碑必须证明阻塞写 owner 时仍能浏览，随后验证内存、启动及重启恢复。缓存未命中的必要远端工作只能留在 owner 慢路径，不能重新污染交互读执行器。

完整规则见[第二阶段设计](../implementation/2026-09-13-interactive-performance-design.md)。内部只读句柄不代表 Desktop 新增只读资源库模式；ADR-0028 和结构一致后才进入主界面的规则继续生效。
