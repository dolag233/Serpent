# 可见窗口上报复用虚拟布局几何

关联 `Serpent-f4622e`、总体性能 `Serpent-3kfe`。仅 Renderer 增量，不改变 Worker 并发、内存预算或上报协议。

## 根因与边界

`collectIntersectingCanvasAssetIds` 每次遍历挂载的布局槽与内层卡片，读取二者的 DOMRect。虚拟画布已经发布供框选、锚定、分页使用的几何索引；固定节拍的可见上报没有复用它。重复读取是已定位的冗余，尚未证明是滚动卡顿主因。

复用既有 `CanvasAssetLayoutIndex`，提供可选的按索引读取资产矩形能力，两种虚拟布局复用各自已有 rectAt 闭包。不生成整库矩形数组、不缓存 DOM 节点跨库或跨布局，不引入 App 内联交互。

上报仍只遍历已挂载候选，保持 DOM 顺序、去重、占位过滤和严格垂直交集。只有布局槽的索引、资产身份与已发布矩形匹配时才使用几何；未知布局、索引/身份不一致及旧版布局退回真实 DOM。每次收集仅缓存本次用到的 grid 原点与候选结果。

发现的契约缺口：平铺行已经显式锁定 bodyHeight，但槽没有显式高度，空槽高度可为零、某些真实卡片也略短于行。仅对可见部分猜测或逐个兜底，仍会留下大部分 overscan 测量。采取与瀑布流相同的根本契约：虚拟平铺外槽显式采用该行已有 bodyHeight，内部卡片高度、预览、caption、行间距和 overflow 不变。外槽因此真实占有已发布几何中的空间；空的真资产槽可在摘要到达前上报，几何占位仍过滤。

这一点有明确的行为变化：外槽透明尾段、摘要未到的空槽也属于可见布局空间，不声称维持零高空槽的旧行为。既有框选/分页本来已按这份完整几何解释空间。普通旧布局不改。需验证空槽到摘要替换、两种布局、caption开关/缩放、滚动边缘与实际DOM一致，避免把“保留内部卡片外观”混同“外槽命中区域完全不变”。临界舍入可回退真实DOM；索引与DOM身份不一致必须回退，不能以测试修改掩盖差异。

## 验证与结果口径

1. 单测证明新旧交集/顺序一致，含边缘接触、部分相交、空槽、重复内层卡片、占位、缺失/旧发布、身份变化、多个 grid 和混合旧布局；证明没有全索引遍历且 DOM 测量数量下降。
2. 真实素材隐藏 Electron 在两种布局和不同滚动位置，对上报 visible 与当时挂载 DOM 的原算法参考结果比较；此正确性观测不混入帧率窗口。
3. 同一 native GPU 稀疏捕获模式、相同源、相同旅程，前后比较矩形读取与帧/远跳数据；保留慢点。减少读取不等于稳定帧率改善。
4. 只运行直接相关 Renderer 测试、局部 lint 与对应 Electron 旅程，不运行无关 Worker、库可用性、20k 或发布全套。前台按用户要求不操作；独立 Luna 双轴复核，人工验收仍由用户确认。

## 挂载新鲜度与所有权补充

真实DOM参考检查发现缓存窗口换挂载成员后可能没有后继report。虚拟组件在index或viewport范围提交后发送独立的冒泡通知，App复用原80ms coalescer处理；发布WeakMap保持纯函数。旧库通知的待执行帧以library ID和view generation检查owner，过期时既不发布也不消费共享deadline。

实施和定向自动化已完成，新 `CANVAS-VISIBLE-045` 待用户验收。最终34项直接测试、两源plain与强化parity通过；源码/构建hash、失败定位、四列证据和性能限制见[开发记录](../development/2026-11-17-viewport-published-geometry.md)。读取次数约降95%～96%，无计数帧耗时未见稳定改善，不标整体目标完成。用户要求此增量收口后停止，不继续扩展优化，不提交推送。
