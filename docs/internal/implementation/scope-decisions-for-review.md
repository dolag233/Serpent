# MVP 切片规格 Scope 决策点（已按默认实现，待产品验收）

> 状态：实现采用 agent 默认值；尚未视为用户逐项确认
> 日期：2026-07-13

7 个 agent 并行写了切片 0004–0010 的规格，随后另一轮实现已在未逐项确认的情况下采用多数默认值。下列项目因此改作产品验收清单：实现存在不表示决定已被接受；发现与产品目标或安全边界冲突时仍需修正。

## 切片 0006（缩略图/预览/解码）—— 影响最大

1. **悬停放大卡片需独立原型验证。** 产品简报要求所有资产卡片悬停放大，视频/GIF 在放大态可播放。验证不通过时 MVP 退回普通卡片 + 显式预览入口。**需确认：** 是否接受"原型验证不通过则降级"的兜底，还是必须做透悬停放大？
2. **EXR 色彩管理 MVP 范围 = 仅默认 OCIO cg-config**，假设 scene_linear 输入并显式标注；专业色彩空间手动覆盖 UI 推迟。**需确认：** MVP 只支持默认 OCIO 配置是否够首发用户用？
3. **外部打开仅单入口**（右键 → 使用外部应用打开）；"打开方式"多候选菜单推迟。**需确认：** 单入口够吗？

## 切片 0009（云端 AI BYOK）—— 依赖 + 安全

1. **视频联系表依赖切片 0006。** 视频 AI 分析需 0006 生成的 contact_sheet artifact。若 0006 未实现联系表，视频 AI 无法工作。当前 spec 未设计 fallback（仅用封面分析）。**需确认：** 是否需要"仅用封面"的临时 fallback，还是严格等 0006？
2. **`structured_metadata` 字段存为 TEXT JSON，子 schema 未定义。** 建议先只支持 label/description/tags 三字段，structured_metadata 作预留。**需确认：** 同意预留？
3. **内置模型清单 = 代码常量**（每版本快照），不走数据库。新模型需发版。**需确认：** 是否需要用户手动输入模型名的 fallback？

## 切片 0007（回收站/找回/批量重新定位）—— 行为差异

1. **链接资产不进 Serpent 回收站。** 删除链接资产仅弹确认（是否同步删磁盘源文件），选"是"→系统回收站后删 DB 记录，选"否"→仅删 DB 记录。与托管资产（进 Serpent 回收站 30 天）路径完全不同。**需确认：** 链接资产是否也应有 Serpent 级回收站？
2. **批量重新定位仅支持指定一个共同新根**——不支持一次性为不同资产指定不同新根。**需确认：** 够吗？
3. **重新定位 keepMetadata 默认 true**（保留 Label/描述/标签/合集/评分/喜欢/源链接/人工色卡）。false 分支清空人工内容。**需确认：** false 分支语义是否符合预期？
4. **linked 资产删除不产生 file_operations 行**（无托管文件需崩溃恢复）。**需确认：** 是否需要审计所有删除？

## 切片 0008（浏览器扩展采集）—— 交互模型

1. **Fire-and-forget HTTP 202**（不推送下载进度）。WebSocket 进度推送推迟。**需确认：** MVP 接受"保存成功仅靠资产出现在网格中作反馈"？
2. **扩展保存遇同名自动 keep-both（追加序号），不弹 UI 冲突窗**（fire-and-forget 模式的必然结果）。**需确认：** 接受？还是需要 chrome.notifications 轻量通知？
3. **Main 维护聚焦窗口的 libraryId + selectedFolderId** 以解析扩展保存目标，经 Renderer→Main 内部 IPC 同步。**需确认：** 与切片 0001 窗口模型兼容？

## 切片 0004（标签/合集/元数据编辑）

1. **asset_metadata 回填通过显式 backfillAssetMetadata 命令**（非迁移自动扫资产表）。**需确认：** 同意？
2. **合集递归汇总去重在 Worker SQL**（parent_id 自连接），Renderer 仅传 recursive boolean。**需确认：** 不改客户端去重？
3. **smart_collection query_definition/sort_definition 本切片仅原样存取**，结构校验等切片 0005。**需确认：** 同意？
4. **palette 存为 JSON 字符串数组**（非独立表行）。**需确认：** 后续不需要改 schema？

## 切片 0005（搜索/过滤/排序/智能合集）

1. **asset_search_content 用独立内容表**（rowid 对齐 FTS5），避免在 assets 加整数 ID 列。**需确认：** 同意？
2. **metadata_text 当前仅含扩展名 + 文件大小区间 + 可用性文本**；分辨率/时长等格式专有元信息由 0006 提取后追加。**需确认：** 同意渐进填充？
3. **中文分词库选型留实现阶段**（从 docs/internal/research/database-and-fulltext-search.md 选），不锁死。**需确认：** 同意？

## 切片 0010（资源库导入导出）

1. **无 export_operations 表**（导出进度在内存 + 事件推送）。**需确认：** 还是需要崩溃恢复？
2. **ZIP 实现选型 TBD**（archiver vs 内置 zlib）。archiver 是 MIT + 流式，但是新依赖。**需确认：** 选哪个？
3. **文件夹导入 = 复制后打开**（会磁盘翻倍）vs **就地打开**（已被 0001 OpenLibrary 覆盖）。**需确认：** 复制后打开是否真的需要？
4. **导出含链接文件夹内容时目录布局未定**（扁平 vs 镜像 vs `_linked/` 子目录）。**需确认：** 选哪个？

## 我的建议

对于"够 MVP 即可"的项（0006 降级兜底、0007 链接资产无 Serpent 回收站、0008 fire-and-forget、0009 预留字段、0010 无 export_operations 表），建议**接受 agent 的默认**以加速。

对于"影响后续不可逆"的项（0006 EXR 色彩管理范围、0009 视频联系表 fallback、0010 ZIP 选型 + 链接内容布局），建议**你显式拍板**——这些改起来贵。
