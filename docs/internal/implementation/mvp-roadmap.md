## 2026-07-28 脚本化 + MCP 优先级调整

产品负责人确认：脚本化与 MCP 比 3D/PBR 预览更重要。此前只读 CLI 基础层已经撤回；本节早期的 stdio 设计已由 ADR-0029/0030/0031 替代。当前自动化入口是 Desktop Console 的受控 JS/TS 脚本和 Desktop 内嵌的本机 loopback Streamable HTTP MCP，公共能力全部经过 `Automation Command Gateway`。

Beads 跟踪：`Serpent-y51c`，子项 `Serpent-y51c.2`–`.10`；跨进程写协调任务保留为 `Serpent-bb56.2`，但不再属于 CLI。

### 现在可以开始的前置层

1. 把领域命令、Zod 输入/结果 schema、稳定错误码和能力/副作用元数据抽成 Desktop、脚本与 MCP 共享的公共契约。
2. 设计并锁定显式资源库选择、稳定 ID/唯一资源库路径引用、Execution 日志和能力授权；不得依赖 GUI 当前选中项。
3. 先做 Desktop Console 脚本与同源 MCP Action：资源库检查、资产/文件夹/标签/合集列出、搜索和任务查询；再按风险分层接通写入、`library.create` / `file.import` 与本机批准。
4. 为上述契约补 Registry、Gateway、沙箱、MCP schema 和独立进程测试；不得直接访问 SQLite、复刻文件操作或绕过 Library Worker。

### 需要等待领域语义稳定后再做的部分

- 导入、移动、重命名、删除/恢复、标签/合集写入、AI 写回等修改命令。
- Desktop 与 MCP 并行写入的 per-library 写租约、持久变更序号、崩溃恢复和 detached job 领取。
- （旧设计，已撤回）MCP stdio 启动器与 Desktop 脚本运行时的打包；当前应按内嵌 HTTP MCP 的生命周期、端口和客户端配置验收。

这样可以立即验证脚本化契约和真实使用价值，同时不把当前 v0.1.0 发布收口拖入多套同时变化的写入语义。完整规范以 [`0023-automation-scripting-mcp-framework.md`](0023-automation-scripting-mcp-framework.md) 为准。

## 2026-07-29 插件平台顶层设计

插件平台以 0023 为基础，不建立平行数据库或文件操作层。标准插件复用受控 JS 运行时和
`serpent` SDK，可信插件运行在独立 Node.js UtilityProcess；后者的权限清单是风险披露，
不能被描述成完整系统沙箱。

插件同时支持用户级和资源库级安装。资源库 Package 与配置可随库同步，但每台设备需要
独立信任；用户级与资源库级同 ID 版本冲突时由用户选择，Serpent 不设隐式优先级。
第一阶段不建设插件社区，只支持本地来源和含预编译 `dist` 的 GitHub 仓库 URL。

完整能力、接口、Hook/Provider 性能规则、输入捕获、安装更新和测试门禁见
[`0024-script-plugin-platform.md`](0024-script-plugin-platform.md) 与
[ADR-0026](../adr/0026-plugin-runtime-installation-and-trust.md)。

Beads 跟踪：`Serpent-upsn`，子项 `Serpent-upsn.1`–`Serpent-upsn.9`。

## MVP 后路线图：3D、PBR 与 HDRI 预览（2026-07-28）

这些能力不改变当前 v0.1.0 发布范围，按“先建立通用模型查看能力，再扩展材质贴图，最后评估专业 DCC 格式”的顺序推进。所有项目都只承诺只读预览，不包含在 Serpent 内编辑、导出或覆盖源文件。

Beads 跟踪：`Serpent-61je`，子项 `Serpent-61je.1`–`Serpent-61je.4`。

### P1：FBX/OBJ 模型预览与 PBR 渲染

这是本组需求中优先级最高的项目。目标是导入或链接 `.fbx`、`.obj` 等常见模型后，在资产查看页提供可交互的模型预览：轨道旋转、平移、缩放、基础灯光/环境控制，以及基于材质与贴图的 PBR 渲染。实施前需要确认模型解析器、WebGL/GPU 兼容性、材质槽与外部贴图路径、动画/骨骼是否属于首版范围，并建立缩略图与可复用预览 artifact 的缓存策略。

### P2：PBR 贴图预览

支持将基础色（Base Color/Albedo）、法线（Normal）、粗糙度（Roughness）、光滑度（Smoothness）、金属度（Metallic）、高度/置换（Height/Displacement）等贴图作为可识别的资产预览。不同通道需要使用对应的中性显示方式，并明确粗糙度与光滑度的反转关系；后续可与模型材质槽关联，但不要求首版自动组装完整材质。

### P2：HDRI 贴图预览

支持常见 HDR 环境贴图的等距柱状图/环境球预览，至少提供旋转、曝光和适应窗口等只读查看能力。需要评估 HDR 解码、色调映射、GPU 内存占用以及缩略图/原图的代理策略。

### P2：3D 动画播放与查看器增强（2026-08-08，`Serpent-hy3a` / 0030-F）

模型动画播放（时间轴、帧步进、播放/暂停控制）与查看器增强，排在 3D 静态预览验收通过之后。Beads 跟踪：`Serpent-hy3a`。

> 2026-08-08 产品决定：0030-G 扩展格式（PLY/DAE/3DS 等，`Serpent-1bdg`）不再计划支持，工单已关闭。

### 研究项：Blend、Maya、3ds Max、Cinema 4D 等 DCC 格式

`.blend`、`.ma`/`.mb`、`.max`、`.c4d` 等格式解析通常依赖专有运行时、版本耦合或外部软件，实施难度和分发风险显著高于 FBX/OBJ。先做可行性研究，比较原生解析、官方/开源导出器、后台转换为 glTF/FBX 和插件方案；在研究结论前不承诺支持，也不把它们作为 MVP 或首个 3D 版本的发布条件。

### 共通前置工作

- 统一模型、材质、贴图和 HDRI 的格式能力声明、技术元数据与不支持原因。
- 明确预览生成失败、缺少外部贴图、超大模型和 GPU 不可用时的降级体验。
- 为大模型和高分辨率 HDRI 建立后台生成、取消、重试、缓存清理和性能基准。
- 在 macOS/Windows packaged 应用中验证 GPU、驱动、沙箱、许可证和安装包体积，再决定具体依赖是否进入默认发行包。

## P2 后续路线图：多窗口与多资源库

支持在同一个 Serpent 进程中同时打开多个窗口，并让每个窗口独立绑定一个资源库。窗口之间应互不干扰，同时共享必要的后台 Worker 能力；同一资源库的写入租约、任务状态、菜单命令和事件刷新需要保持一致。

实施前需要完成窗口路由与生命周期设计，明确外部资源库操作、菜单/托盘、插件、扩展和 MCP 的目标窗口规则，并覆盖不同资源库、同一资源库、关闭窗口和应用重启等场景的 Electron E2E 及 macOS/Windows packaged 验证。

当前仅作为 MVP 之后的 P2 能力规划，不属于现阶段发布阻断项。工单：`Serpent-638121`。
