# Issue #75：大库导航与 OIIO 路径修复方案

日期：2026-10-31。状态：方案已制定，尚未编码。依据：[隔离复现与诊断](../research/2026-10-31-issue-75-large-library-diagnosis.md)。

## 目标与决策

本轮解决两个已复现的问题：文件路径中的字面 `#` 导致 OIIO 预览失败；链接目录的同步递归枚举与并发重复计算阻塞 Worker。原始会话中约 54 秒的等待尚无分段耗时，不能把本方案的局部测试结果当作该会话的完整归因。

采用以下实现方向：

1. 所有 OIIO 图片调用默认将路径按字面处理；历史失败按新生成器版本分批重试一次。
2. 链接目录结构持久化为 Worker 拥有的派生索引。导航、文件夹卡片和忽略设置读取同一索引，不在这些请求里遍历源磁盘。
3. 复用现有异步扫描、watcher 合并、对账取消与 scheduler 让出机制更新索引；同一版本的导航构建只执行一次。
4. 计数投影按链接根、资产成员版本和显示策略复用。预览生成进度不触发目录扫描或重新统计整个库。
5. 保留首次开库的库身份与已知结构一致性屏障；外部磁盘扫描从这道屏障移出。具体延迟以分段指标和可见图片解码证据验收。

不通过增加后台并发来消除阻塞。也不只在 `getLibraryNavigationSummaryAsync` 外包一层缓存：那仍会留下首次读取、文件夹卡片和忽略设置的全量同步遍历。

## 既有实现的复用与调整范围

| 能力 | 当前实现 | 本次用途 |
| --- | --- | --- |
| OIIO 预算、并发和取消 | `LibraryService.runOiio`，`mediaNativeMemoryBudget`、`oiioDecoderSemaphore` | 保持现有资源门禁，增加统一的字面路径参数构建 |
| OIIO 的另一个调用入口 | `src/worker/fbx/oiio-texture.ts` | 复用同一参数规则，避免临时目录祖先含 `#` 时再次出错 |
| 失败工件修复与队列 | `enqueueMissingThumbnails`、`requeueLegacyRawColorTransformFailures` | 扩展为有版本条件的 OIIO 路径修复，保持有界分批和队列去重 |
| 异步扫描 | `enumerateSourcesAsync`、`collectManagedAssetDiscoveryAsync` | 在已有目录遍历中记录目录，包含空目录，不再另扫第二遍 |
| watcher 与对账 | `scheduleWatcherRefresh`、`refreshLinkedWatcherFileChanges`、`yieldReconciliation` | 合并目录变化，复用取消、代际校验和后台让出 |
| 路径与忽略语义 | `normalizeRelativeAssetPath`、`portablePathIdentity`、既有忽略 matcher | 不另建大小写、Unicode、符号链接或忽略规则 |
| 导航缓存 | `navigationSummaryCache`、`browse_change_sequence` | 增加构建中的请求合并和根级失效，不用宽泛的媒体进度失效 |
| 链接目录读者 | `listLinkedFolders`、`listLinkedFolderBrowseEntries`、忽略目标枚举 | 统一读取目录投影，消除三处重复磁盘遍历 |

新逻辑拆到独立的 OIIO 参数/错误模块与链接目录读模型模块。`library-service.ts` 负责生命周期接线，不继续承载完整的新缓存和索引算法。

## A：OIIO 的字面路径与失败恢复

### 调用契约

在共享的 OIIO 参数构建入口中，把 `--wildcardoff` 放在任何输入和输出文件名之前。缩略图、全尺寸查看图、颜色信息探针、EXR 分层探针以及 FBX 贴图转换全部使用该入口。审计仓库内其他生产调用点；只有明确处理序列模式的独立调用才允许显式开启通配符，普通图片调用不得自行开启。

继续使用进程参数数组，不通过 shell 引号、重命名源文件或复制大图来绕过路径问题。显式文件列表形式的序列处理保持原有语义。

### 错误语义

资源不足和取消继续走现有专用路径。只有已识别的颜色配置/变换失败才记录 `OIIO_COLOR_TRANSFORM_FAILED`；输入解析、写文件或无法分类的非零退出统一使用既有 `OIIO_GENERATION_FAILED`，内部诊断补充可确认的失败阶段。不能根据 `No filenames found matching pattern` 就把资产标为 missing；只有文件系统核验才能修改源文件可用性。

这一阶段优先复用现有对外错误码，不为诊断细分扩张 Main/Preload 协议。新增日志只记录耗时、阶段、错误码及现有标识，不把命令行中的真实路径写进开发证据。

### 历史失败恢复

成功和失败工件的 `generator_version` 都加入字面路径策略版本标记。候选必须同时满足：当前 revision、旧 OIIO 生成器、未失效的失败工件、源可用、没有正在排队/运行/暂停的同类任务，以及解析后的完整源路径包含 `#`。完整路径包含链接根或资源库根，不能只查相对文件名。

历史工件没有保存可查询的具体输入错误，故无法百分之百识别原来是否正是通配符故障；这里允许符合上述窄条件的旧失败额外尝试一次。新尝试失败后带新标记，不会因再次开库无限重排。已 ready 的工件不失效；删除资产、旧 revision 和不可用源不重试。缩略图复用既有分批队列，全尺寸查看图在查看时恢复；不会一次性解码整个库。

## B：从磁盘遍历改为目录读模型

### 持久化结构

新增可重建的链接目录投影，采用加法 schema 迁移，不改资产文件和 revision 身份：

- 目录项：链接根 ID、规范化相对目录路径、路径身份、父目录身份、扫描 generation。
- 根状态：当前可读 generation、扫描状态、根结构版本、影响扫描的变更版本。
- 唯一键按根、generation、路径身份；父目录索引支持直接子项读取。

目录项只存相对路径，不新增源绝对路径副本。资产衍生的非空目录与扫描发现的真实目录合成一套结构；空目录因此可跨重启保留。离线根继续读取最后一次完整结构。

扫描使用独立 generation 分批写入。只有整个目标范围成功、根仍是同一个根且没有冲突变更时，才在短事务中切换可读 generation；取消、权限错误或磁盘断开不能把未扫到的目录当作已删除。过期 generation 由同一生命周期清理，进程退出遗留在下一次打开时有界回收。派生索引可以重建，但不能把“读不到磁盘”解释为“目录为空”。

### 数据如何更新

| 触发 | 更新行为 |
| --- | --- |
| 首次链接导入 | 已有扫描同时收集文件和目录，完成后发布结构；不增加第二次磁盘递归 |
| 开库对账 | 先服务已存目录结构；在现有异步遍历中顺带刷新目录 generation |
| 外部目录新建、删除、改名 | watcher 按根和脏子树合并；已知子树做局部重扫，模糊事件才做根级后台扫描 |
| 应用内创建、改名、移动、删除 | 复用现有对账取消边界，操作成功后更新索引和结构版本；失败不发布目标结构 |
| 文件成员或可用性变化 | 只让受影响根的计数投影失效；不扫描目录 |
| 忽略规则或显示选项变化 | 复用 matcher 更新可见性与计数；需要发现此前未扫描的目录时在后台补齐 |
| 链接根离线、重连、换根 | 离线保留最后完整快照；重连重扫；换根使旧 generation 构建失效并建立新根版本 |

新索引中的扫描覆盖范围必须包含适用的规则版本。目录元数据的覆盖范围复用当前忽略目标枚举的语义：链接根规则继续限制遍历，符号链接不跟随；被 `.serpentignore` 隐藏的目录仍可记录为忽略设置的候选，资产发现和导入继续应用原有忽略规则。目录记录与资产收录是两个独立决定。已显式忽略的目标还要与既有忽略记录合并，避免索引尚未补齐或源离线时丢失取消忽略的入口。测试必须对照当前导航、显示忽略项和忽略设置三种口径，不能以缓存为由改变产品语义。

### 旧库升级与冷启动

迁移只建立表和索引，不同步遍历用户源目录。旧库先根据已有资产路径分片构建非空目录投影，使用现有路径身份与忽略语义；这一步不得放在单个巨大事务或不可取消的事件循环片段中。首个可用目录快照只依赖库内数据。

旧库此前未记录过的空目录会在首次后台扫描后补齐；之后重启直接读取已持久化的空目录。此行为要在人工验收中覆盖，不给用户增加实现细节文案。

### 计数与请求合并

根级目录结构和资产计数分开失效。计数缓存使用“根成员版本 + 忽略/缺失显示策略”，从当前查询语义选出的可见资产一次聚合并复用；不能忽略回收站、序列隐藏帧、显式忽略和缺失文件规则。首次大根的聚合也需分片并能让出；若约 15 万资产的测量仍超预算，再把直接计数持久化，避免在未测量前引入多套长期计数真相源。

相同库实例、浏览版本和显示选项的导航构建只保留一个共享 Promise。不同消费者共享结果，某个消费者取消不能取消其他消费者需要的构建；切库/关闭由库生命周期统一取消。旧构建不能覆盖新 key 的缓存，`finally` 只能删除自己对应的 in-flight 项。一个请求失败不能永久卡住缓存。

导航、链接文件夹卡片、忽略设置都使用同一结构和计数投影；不得保留一个“缓存未命中就同步递归全盘”的兜底。

## 调度与首屏

继续使用既有 async 目录枚举和 `yieldReconciliation`，复用当前条目数/时间片检查；扫描等待源盘时不能独占可见媒体查询的 admission。同步 SQL 和内存聚合也必须记录最长单段耗时，不能认为函数标了 async 就已经可抢占。

先去掉导航请求内的源磁盘 I/O，再评估其是否满足 maintenance 状态读的成本约束。若冷投影构建仍是长任务，将构建作为独立后台 owner，在安全点释放 admission，导航读已发布快照。不能直接移除 `library.navigation-summary` 的并发例外而让开库重新等待整段 maintenance。

渲染器沿用首次库身份与已知结构的屏障，不通过提前移除 loading 来掩盖后端等待。普通文件夹切换复用现有 sidebar，外部新增结构通过版本化变更事件渐进补齐。

## 测量与验收

把现有两项临时诊断改为永久、跨平台的回归测试，修复后断言正确行为。性能数值作为当次证据；共享机器上不把某次 wall-clock 波动直接定性为产品通过或失败。确定性的约束包括：导航热路径零次源目录枚举、同 key 只构建一次、失败扫描不发布空快照。

| 需求条目 | 计划实现位置 | 自动化证据 | 人工/平台证据 |
| --- | --- | --- | --- |
| OIIO 字面路径和正确分类 | 共享 OIIO 参数/错误模块、Worker 与 FBX 调用入口 | 真实 OIIO 处理祖先目录含 `#` 的 TGA/BMP/EXR；探针和查看图检查；颜色错误与输入错误分别断言 | Windows/macOS 媒体预览未执行；图片需实际解码 |
| 旧失败只恢复一次 | 有版本条件的失败修复、原有媒体队列 | 旧失败恢复、新版本失败不循环重排、ready/旧 revision/不可用源不受影响 | 用户旧库恢复未执行 |
| 读路径无磁盘枚举 | 链接目录投影及三类读者 | 将源枚举设为抛错时导航/卡片/忽略读取仍成功；空目录完整退出重启后保留 | 真库浏览未执行 |
| 同 key 合并与版本隔离 | navigationSummaryCache 的 in-flight 协调 | 并发只构建一次；变化中途发生、失败、单消费者取消、切库/关闭后结果不串库 | 切库未执行 |
| 索引一致与回收 | 加法迁移、扫描 generation 发布、watcher 接线 | 扫描失败/取消、权限错误、离线重连、改名/删除、规则变更、重启遗留清理及磁盘对账 | Windows/macOS 文件监视语义未执行 |
| 大库可交互 | 调度让出与根级计数投影 | 保留 2 万混合基线；新增约 15 万链接资产、4,100 空目录、深目录及可控慢枚举；采集 p50/p95、最大事件循环间隙和媒体等待 | 真实 Electron 首屏解码、连续切文件夹和独立进程重启未执行 |

目标沿用仓库产品预算：约 1 秒内明确库身份和阶段，文件夹首屏目标 500 ms；可见媒体路径解析不随后台遍历整段等待。额外比较当前诊断中的 562 ms 单请求、1,076 ms 双请求与 975 ms 事件循环间隙。成功标准是消除目录枚举与重复构建，而非承诺所有存储介质都满足某个未实测的绝对值。

阶段计时包括 scheduler 等待、导航各部分、目录扫描与发布、source 路径解析、响应及浏览器首个图片解码。慢段日志默认仅输出必要的聚合信息，详细采样通过现有诊断开关启用。JPG 空白需靠 source 响应及 `complete && naturalWidth > 0` 单独验收，不能随 OIIO 修复顺带关闭。

实施涉及 schema/开库与媒体管线，按实际改动运行资源库可用性、直接相关 Worker 测试和真实 Electron 旅程；不自动触发 `verify:mainline` 或 `release:verify`。E2E 串行后台运行并隔离 userData，测试产物同生命周期清理。

## 交付顺序与完成边界

1. **OIIO 路径修复**：参数规则、错误分类、版本化历史失败恢复、对应测试；作为独立功能提交/PR。
2. **链接目录读模型**：先加入分段测量和可重建 schema，接入异步扫描/变更，再替换全部读者、合并导航请求并验证调度；作为另一项功能提交/PR。
3. **规模与真实应用验收**：比较相同夹具的前后数据，独立审查索引一致性和失败恢复，再由真实 Electron 与用户库证据收口。

两项功能各自达到验收再进入发布。目录索引在慢盘上的首次扫描仍可能很久，但其耗时不得成为导航和可见预览的前置条件。原始会话的 54 秒等待、截图中的 JPG 空白以及真实用户库恢复，在取得对应证据前持续标为未验证。
