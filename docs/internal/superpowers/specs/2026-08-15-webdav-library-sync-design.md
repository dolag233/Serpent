# Serpent 资源库同步顶层设计（WebDAV 首版）

> 日期：2026-08-15  
> 状态：顶层设计完成，待实现认领  
> 研究：`docs/developer/research-webdav-sync.md`  
> 相关：资源库导入/导出（`library export/import`）已证明"交换格式"与派生文件排除可行

## 1. 目标与用户场景

**Story 1（单人双设备）**：用户 A 在家有一个资源库，想在公司也能使用同一资源库，双向同步——两边都能修改，改动互相可见。

**Story 2（多人共享参考库）**：同一家公司的美术 A/B/C/D 共享一个资源库，谁都可以修改内容，共同维护一个参考资源库。

首版交付边界：

- **文件级并发**：不同资产可同时被不同设备修改，互不干扰；只有同一资产两边都改才进入冲突处理。
- **冲突副本**：同一资产双侧修改时，采用"后写者胜（Last-Write-Wins）+ 冲突副本"策略——一方版本成为正式文件，另一方保存为 `name (conflict-YYYYMMDD-HHMM).ext` 并通知用户；首版不做自动内容合并。
- **无权限角色**：Story 2 首版所有参与者可写；权限、操作日志、变更推送放后续阶段。

## 2. 设计原则

1. **服务器无状态**：远端只是被动文件存储（WebDAV 目录），不维护锁、会话、用户或任何业务状态。参考 Git/Syncthing/Joplin——正确性由客户端乐观并发保证，而不是服务端锁。锁状态会过期、会脏（设备断电后无人解锁），维护它只会引入新的正确性问题。
2. **SQLite 永不上传**：远端是**交换格式**，不是库目录镜像。多设备并发写同一个 SQLite 文件必然损坏；本地库永远是唯一权威数据库，远端只存资产与元数据的交换表示。
3. **原文件按库内文件夹结构存放**：远端 `assets/` 与库内文件夹层级一致，用户仍可在 NAS 文件管理器/图片浏览器中按文件夹浏览原图（折中形态：结构可读，元数据机器化）。
4. **派生文件不同步**：缩略图、联系表、webm proxy、色板、AI 结果全部本地重建（Joplin 同策略），远端只存原始资产 + 用户元数据。
5. **乐观并发 + 条件写**：写前比对 manifest 版本；服务端支持 ETag 时用 `If-Match` 做 CAS（比较并交换）；不支持时退化为"检查后写"，窗口极小且失败有冲突副本兜底，绝不静默覆盖。
6. **删除必须显式**：删除 = 远端墓碑 + 本地回收站语义。空目录 ≠ "用户删了全部"；首次连接、路径错误、权限不足与真正删除必须区分。
7. **时间戳只是辅助信号**：版本判定依赖内容哈希与版本号，`getlastmodified` 不单独决定覆盖。

## 3. 领域语言

| 术语 | 定义 |
| --- | --- |
| 同步单元（Sync Unit） | 参与同步的最小对象：资产文件（assetId → 内容哈希）或元数据条目（assetId 的标签/评分/描述等，独立版本） |
| 远端根（Remote Root） | 一个 WebDAV 地址（含凭据），可承载**多个资源库**；每个库占用其下一个以库名命名的子目录 |
| 库目录（Library Directory） | `<远端根>/<库名>/`，该库同步空间的顶层；其 manifest 记录 libraryId 完成绑定校验 |
| Manifest | 远端根下的权威版本清单，每条目含 `path`、`contentHash`、`version`、`deviceId`、`modifiedAt` |
| 冲突副本（Conflict Copy） | 双侧同资产同时修改时，未获胜版本在获胜设备本地与远端各保存一份的 `name (conflict-…)` 文件 |
| 墓碑（Tombstone） | 删除在远端的显式标记（`trash/<assetId>.json`），使删除可跨设备传播且可追溯 |
| 能力探测（Probe） | 连接配置后一次性探测：认证方式、PROPFIND 递归深度、ETag/If-Match、锁、配额、路径编码、单文件大小限制 |
| 同步任务（Sync Job） | 一个可恢复、可暂停、可重试的传输单元（上传/下载/删除/元数据写），带进度与断点状态 |

## 4. 架构分层

```text
Renderer（同步设置页 / 状态角标 / 冲突通知 / 进度）
   │ typed commands/events
   ▼
Library Worker（SyncEngine — 同步的唯一所有者，与库数据同进程）
   ├─ 变更收集：本地变更表（insert/update/delete 钩子 + 文件指纹）
   ├─ 版本比对：本地 manifest 缓存 ↔ 远端 manifest
   ├─ 冲突决策：哈希/版本比对 → LWW + 冲突副本
   ├─ 任务队列：大文件优先级的可恢复 Job，进度/暂停/取消/重试
   └─ 墓碑与删除传播
        │ 驱动接口（list/get/put/delete/exists + probe）
        ▼
   RemoteStorageDriver（抽象层）
        └─ WebDAVDriver（PROPFIND/PUT/DELETE/MKCOL/MOVE；
                         Basic/Digest 认证；凭据经系统凭据存储）
           后续：S3Driver、Serpent Cloud
```

关键边界：

- 同步引擎放在 **Library Worker**（与 SQLite 同进程），避免跨进程搬移大文件元数据；网络传输本身仍由 Worker 内的 HTTP 客户端执行（复用现有 bounded-write 与诊断习惯）。
- Renderer 永不接触凭据与远端 URL 之外的敏感信息；凭据只在配置时经 Main 写入系统凭据存储（Windows Credential Manager / macOS Keychain，Electron `safeStorage` 兜底加密）。
- `RemoteStorageDriver` 是同步语义无关的纯文件操作接口，WebDAV 只是第一个实现。

## 5. 远端布局（交换格式）

```text
<Remote Root>/                      # WebDAV 根，可含多个库
  <库名>/                            # 每个资源库一个子目录
    manifest.json                    # 版本清单（唯一权威版本索引）
    assets/
      <库内文件夹路径>/<文件名>        # 原始资产，按库内文件夹结构
    metadata/
      entries/<assetId>.json          # 该资产的用户元数据条目（标签/评分/描述/合集成员等）
    trash/
      <assetId>.json                  # 删除墓碑（含删除设备/时间/原路径）
    .serpent-sync/
      format-version                  # 交换格式版本（仅加不改，向下兼容）
```

约束：

- 库目录名 = **库显示名**；manifest 内记录稳定 `libraryId`，用于绑定校验与同名冲突检测。
- **一个远端根可承载多个库**；一个库同一时刻只绑定一个远端根上的一个库目录。配置界面按「远端根 → 库」两级组织：先配根（URL/凭据），再为各库选择/绑定目录。
- **库重命名**：库目录随之改名——同步引擎用 WebDAV `MOVE` 迁移整个库目录；服务端不支持 MOVE 或迁移失败时回滚并明确提示（首版不做"远端两处目录并存"的兼容态）。
- **同名冲突**：库目录已存在但 manifest 的 `libraryId` 与本地库不一致 → 判定为不同库撞名，明确报错并给出改名或另选目录的选项，绝不自动写入。
- `assets/` 内的相对路径即库内 `relativeFilePath`（portable path），跨平台路径统一 `/`。
- 文件名冲突（Windows 非法字符、大小写不敏感）沿用库内导入的既有处理；同步不改名资产。
- `metadata/entries/` 用 assetId 而非路径寻址——移动/重命名只改 manifest 条目，不改元数据文件。
- 派生目录（`.serpent/`、`artifacts/`）绝不上传；本地缩略图缺失由各设备重建。

### Manifest 条目（示例）

```json
{
  "formatVersion": 1,
  "entries": {
    "<assetId>": {
      "path": "概念图/机甲/boss-01.psd",
      "contentHash": "sha256:…",
      "size": 104857600,
      "version": 7,
      "deviceId": "dev-8f3a",
      "modifiedAt": "2026-08-15T09:12:00Z",
      "etag": "\"9a3b…\"" ,
      "metadataVersion": 3
    }
  }
}
```

- `version` 是每条目单调递增的写入计数；`etag` 是上次写远端返回的服务端 ETag（有则用于下次 CAS）。
- manifest 本身也是文件：写入用"读-改-写 + If-Match"；服务器不支持条件写时，写入前重读比对，冲突时以条目级合并（双方条目各取新者），manifest 条目冲突以 `(version, modifiedAt, hash)` 顺序裁决。
- 单库资产可能上万：manifest 按需分层读取（先取条目哈希索引，再取明细），避免每次同步全量下载；首版接受"整文件下载 + 本地缓存"，分片放二期。

## 6. 同步流程

### 6.1 连接配置与认证

- 配置项：WebDAV 根 URL、用户名、密码/应用专用密码（Nextcloud 场景）、库绑定确认。
- 认证自动协商 Basic/Digest；支持 401 `WWW-Authenticate` 探测。
- **仅 HTTPS**：HTTP 明文连接默认拒绝并明确警告（用户可显式确认仅局域网自用）；凭证只走系统凭据存储，绝不写入库、日志或任何 `.json`。
- 连接测试：MKCOL 探测目录 + PROPFIND 根 + 写入/删除临时探测文件；失败返回可读错误（401 凭据错误 / 403 权限 / 404 路径 / 507 配额 / 超时）。
- **多库共享一个远端根**：根下按库名建目录（见 §5）；同一根上的不同库共享凭据配置，绑定各自目录。库目录的 manifest 记录 `libraryId`，与本地库不一致（撞名）时明确报错，不自动写入。

### 6.2 首次同步

1. 配置连接 → 连接测试 → 探测能力（见 6.4）。
2. **首次同步预览**：列出本地与远端条目差异（新增/更新/删除/冲突，按数量与大小汇总），用户确认方向策略：
   - 根下无该库目录 → `MKCOL` 链创建 `<库名>/` 结构，全量上传（建立初始 manifest）；
   - 库目录存在且 `libraryId` 匹配（新设备）→ 全量下载后本地重建库与派生文件；
   - 库目录存在但 `libraryId` 不匹配 → 撞名报错，请用户改名或另选目录；
   - 两边都有且绑定一致 → 逐条 LWW/冲突副本预览，用户确认后执行。
3. 预览与执行分离，执行前可取消。

### 6.3 增量同步（正常运行）

1. **收集**：本地变更表（导入/编辑/重命名/移动/删除/元数据变更均落 sync-change 记录）→ 计算文件指纹（size + mtime 快速通道，hash 确认）。
2. **拉取远端 manifest**（缓存 + 增量）。
3. **逐条目决策**（文件级，互不影响）：
   | 本地 | 远端 | 动作 |
   | --- | --- | --- |
   | 未变 | 新/变 | 下载 |
   | 变 | 未变 | 上传 + 更新 manifest |
   | 变 | 变（同 hash） | 仅更新 manifest（内容已一致） |
   | 变 | 变（异 hash） | 冲突：LWW 定正式版本，败者存冲突副本（双端），通知用户 |
   | 删除 | 未变 | 写墓碑 + 删远端文件 |
   | 未变 | 删除（墓碑） | 本地进回收站（保留恢复能力） |
4. **应用**：资产写入走既有导入/修订管线（revision + 缩略图重建），元数据条目合并进 SQLite；全部应用成功后才推进本地 manifest 缓存。
5. **收尾**：诊断摘要（传输量/失败列表/冲突列表）→ Renderer 同步历史。

元数据条目（标签/评分/描述）的冲突：首版同样 LWW；因是结构化字段，二期可做"双侧各加标签自动并集"这类合并（见阶段路线）。

### 6.4 能力探测（Probe）

连接后一次性探测并缓存结果：

| 能力 | 探测方法 | 首版行为 |
| --- | --- | --- |
| 认证方式 | 401 `WWW-Authenticate` | Basic/Digest 自动 |
| PROPFIND 递归 | Depth: infinity 请求 | 不支持则分层遍历 |
| ETag / If-Match | 写临时文件后条件写 | 支持→CAS；不支持→检查后写 |
| 锁支持 | OPTIONS / LOCK 探测 | 不使用（无状态原则），仅记录 |
| 配额 | 207 `quota-*` 属性 | 展示剩余空间 |
| 单文件大小限制 | 服务端文档/实测 | 超限资产标记"不同步"并说明 |
| 路径编码 | 特殊字符文件探测 | 冲突字符本地记诊断，不改名 |

### 6.5 大文件与任务队列

- 首版：整文件 PUT/GET + 可恢复 Job（重试指数退避、暂停/取消、跨重启状态持久化）；上传用临时文件 + 最终 MOVE 减少半成品可见。
- 传输并发上限（默认 2，可配）；大文件（>100MB）单独排队，小文件批量先行——首版不打断。
- 断点续传（分块/range）：二期，按探测结果选择 chunk 策略；不支持续传的服务端保留任务状态与重试，绝不谎报成功。

### 6.6 删除与墓碑

- 本地删除资产 → 远端写 `trash/<assetId>.json`（含设备/时间/原路径）+ 删除远端文件。
- 他端看到墓碑 → 本地移入回收站（不直接硬删），用户可从回收站恢复；恢复则清墓碑。
- 清空回收站/永久删除 → 墓碑置 `purged`，他端本地硬删。
- 首次连接远端为空目录 ≠ 全删；远端 manifest 存在而本地空才视为新设备下载。

## 7. 安全与隐私

- 凭证入系统凭据存储；连接与凭据校验错误统一可读文案（不暴露堆栈）。
- 明文 HTTP 警告；默认仅 HTTPS。
- 首版不承诺端到端加密（调研已明确：E2EE 需内容加密 + 密钥恢复流程，另立专项）；文档与 UI 如实说明"WebDAV 服务端管理员可读取原始资产"。
- 同步日志脱敏：不含凭据，路径可按用户设置脱敏。

## 8. UI 设计

- **入口**：资源库设置（侧栏资源库菜单 → 设置）新增「同步」页，两级组织：**远端根管理**（URL/用户名/密码 + 测试连接，一个根可服务多个库）与**当前库绑定**（选择已配置的根 → 绑定/切换 `<库名>` 目录 → 绑定状态）、同步历史（时间/设备/传输量/失败/冲突）。
- **顶栏同步角标**：空闲/同步中（进度）/有冲突/失败（红点，点击进同步页）；复用既有后台任务 UI 体系与主题 token，不新造样式。
- **首次同步预览对话框**：差异汇总（新增 N / 更新 N / 删除 N / 冲突 N，总大小），方向说明，确认后执行。
- **冲突通知**：notice + 同步页列表（资产名、双方时间、操作：保留我的/保留对方的/打开冲突副本）。
- **进度与暂停**：同步页进度条 + 暂停/恢复；后台继续，关闭设置页不中断。
- 所有文案遵循既有语气规范（无焦虑、无阻塞窗），中英文双语。

## 9. MVP 范围与非目标

**首版（Phase 1）**：

- WebDAV 双向同步；一个库绑定一个远端根上的一个库目录（`<根>/<库名>/`），一个远端根可承载多个库；文件级并发 + 同资产冲突副本；
- Basic/Digest 认证 + 应用专用密码 + 系统凭据存储 + HTTPS 强制；
- 能力探测、连接测试、首次同步预览、增量同步、墓碑删除传播；
- 可恢复传输 Job（重试/暂停/取消/持久化），进度与同步历史；
- 派生文件不同步，SQLite 不上传，资产与元数据分开版本。

**非目标（首版不做）**：

- 分块断点续传（二期）；元数据自动合并（二期）；
- 建议锁/在场提示（"张三正在编辑"）（三期，纯 UI 提示，不参与正确性）；
- 权限角色、操作日志、变更推送（三期）；
- S3 等其他 driver、Serpent Cloud、E2EE；
- 实时协作（Logseq 式 RTC）。
