# UI direction 0006: Progressive loading UX principles

> Status: active product/UX constraint  
> Date: 2026-08-14  
> 关联：产品简报「MVP 性能行为」；`library.open` / 资源库打开；缩略图默认占位；查看页 mip 升级

## 核心原则（一句话）

**禁止同步阻塞加载。用户操作必须先进入可交互界面；未就绪的内容用 placeholder，在后台继续完成。**

打开资源库、浏览画布、查看原图、搜索与导入等凡是会碰到 IO / 解码 / 迁移瓶颈的路径，都按这条执行。不得为了「一次拿齐」而让用户空等。

## 1. 打开资源库

- 用户点击打开资源库后，**力争约 1 秒内**进入可交互主界面（可切换文件夹、滚动、选择、搜索）。
- 不得等 schema 迁移、全库扫描、缩略图生成、AI、索引重建全部完成后再显示。
- 未加载好的缩略图使用默认缩略图/文件图标占位，就绪后安静替换；不得闪破图或整页空白。
- 把 `library.open` 超时从 15 秒改到 5 分钟只是启动失败的应急处理，**不是**本原则的实现。用户不应感知「打开库要等几分钟」。

## 2. 所有 IO 瓶颈都渐进

适用面至少包括：

- 打开 / 切换资源库
- 资产列表与文件夹树
- 缩略图、预览、原图解码
- 搜索索引、过滤首屏
- 导入、磁盘对账、后台任务

共同规则：

1. **先可交互，再补齐。** 首屏用已有缓存或占位。
2. **占位必须稳定。** 卡片尺寸、布局、选中态不因占位→真实内容而抖动（与画布布局纪律一致）。
3. **升级要安静。** 缩略图→预览→原图可以变清晰，但不得重置用户已做的缩放、平移、滚动位置。
4. **失败不阻断。** 单项 IO 失败只影响该项，不让整个资源库或查看页卡住。

## 3. 反例

- 启动时同步跑完 `library.open`（含迁移）才显示窗口内容。
- 双击查看时等到原图解码完才出画面，或升级原图时把视图打回 Fit。
- 滚动时把已有缩略图卸掉换成默认图标再重新加载。
