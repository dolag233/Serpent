# UI direction 0006: Library safety and progressive loading UX principles

> Status: active product/UX constraint  
> Date: 2026-08-14  
> Product revision: 2026-08-28 — library opening/switching is a safety boundary; this revision takes precedence over the original blanket progressive-loading rule.
> 关联：产品简报「MVP 性能行为」；`library.open` / 资源库打开；缩略图默认占位；查看页 mip 升级

## 核心原则（一句话）

**给用户以安全感：资源库打开/切换先确保结构一致，只有持续超过 3 秒才显示简洁的等待提示；普通内容浏览仍然渐进加载。**

“渐进式加载”不是所有路径的同一套交互。对于可能持续很久、且一旦显示不完整就会让用户担心文件夹/合集丢失的资源库边界，明确的等待状态比一个看似可用但不完整的首屏更安全。

## 1. 打开资源库

- 用户点击打开或切换资源库后，若 3 秒内完成，不显示加载窗口，避免一闪而过造成 glitch；若持续超过 3 秒，只显示一行“正在打开 xx 资源库”（未知名称时使用通用文案）和“切换资源库”按钮。
- 在资源库结构、文件夹、链接文件夹、合集、智能合集、标签、回收站摘要和首批资产查询形成同一份可用快照前，**不得展示新资源库的主界面首屏**。旧资源库的导航也不能继续留在首屏，避免用户误以为数据被删除或串库。
- 加载窗口不展示阶段、进度条或额外解释；不伪造用户无法验证的进度，也不把普通后台任务混入打开提示。
- 加载过程中仍须保留“切换资源库”入口。它只排队下一次切换，不破坏当前打开流程；如果当前流程失败，窗口消失后资源库切换入口仍可用。
- 资源库打开成功后，先提交完整导航快照，再安静地显示主界面；缩略图生成、AI、尺寸探针等不属于进入主界面的必要条件，仍可在后台渐进完成。
- 把 `library.open` 超时从 15 秒改到 5 分钟只是启动失败的应急处理，**不是**本原则的实现。用户不应感知「打开库要等几分钟」。

## 2. 普通内容路径继续渐进

以下路径默认先给出可用首屏，再在后台补齐：

- 资产列表与文件夹树的普通范围切换
- 缩略图、预览、原图解码
- 搜索索引、过滤首屏
- 导入、磁盘对账、后台任务

共同规则：

1. **先可交互，再补齐。** 首屏用已有缓存或占位。
2. **占位必须稳定。** 卡片尺寸、布局、选中态不因占位→真实内容而抖动（与画布布局纪律一致）。
3. **升级要安静。** 缩略图→预览→原图可以变清晰，但不得重置用户已做的缩放、平移、滚动位置。
4. **失败要可理解。** 普通单项 IO 失败只影响该项；资源库边界失败则要说明原因并保留切库能力，不能用空白或半套数据掩盖问题。

资源库加载窗口覆盖的是“身份与结构确认”阶段，不等于把所有资产缩略图、AI 结果或后台索引都同步做完。完成结构快照后，主界面仍按普通渐进式规则运行。

## 3. 反例

- 打开库时直接显示旧库或新库的部分文件夹/合集，让用户猜测剩余数据是否丢失。
- 没有资源库名称或反馈地长时间阻塞窗口。
- 用阶段文案、进度条或额外解释制造虚假的确定感。
- 双击查看时等到原图解码完才出画面，或升级原图时把视图打回 Fit。
- 滚动时把已有缩略图卸掉换成默认图标再重新加载。
