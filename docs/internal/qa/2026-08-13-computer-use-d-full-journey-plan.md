# Computer Use 全流程验收计划

日期：2026-08-13
阶段：D（重做版）
目标：使用真实 Serpent UI，按用户目标完成全流程验收；不以“页面打开”或单个按钮点击作为通过。

## 验收原则

1. 每个目标都从用户意图开始，以可观察的结果结束，并至少验证一次后续操作仍然成立。
2. 所有操作通过 Computer Use 完成。脚本、MCP、插件等自动化能力也通过可见的设置页、脚本控制台和外部可视终端/客户端操作，不用源码、数据库或隐藏 API 代替 UI 验收。
3. 涉及删除、覆盖、永久删除、清空回收站、修改凭据或外部权限的步骤，只验证确认界面和取消路径，不执行不可恢复动作；可恢复的移入回收站和恢复会实际执行。
4. 使用两个资源库：一个一次性临时验收库承载创建、导入、删除和破坏性流程；一个现有资源库承载大规模浏览、媒体和重启恢复。不得污染用户真实素材。
5. 每个目标记录：前置状态、Computer Use 操作、界面结果、数据结果、截图、失败/阻塞原因和覆盖的功能 ID。只有五项齐全才能写“通过”。
6. macOS 结果与 Windows 结果分开记录。当前机器不能把 macOS 的人工证据写成 Windows 通过；Windows 窗口、路径、托盘、GPU/WebGL 和安装器另列未执行。

## 验收数据集

临时库需要准备一组小而完整的混合素材：普通图片、超长文件名图片、视频、音频、文本、连续序列帧、OBJ/MTL、glTF/GLB、STL、FBX、PBR 通道贴图和 HDRI；另准备同名同内容、同名不同内容、不同名同内容、缺失源文件和外部修改文件。媒体只使用合法的本地 fixture，不从真实用户目录扫描导入。

## 执行顺序

1. D-01 建立临时库并记录干净基线。
2. D-02～D-04 完成导入和组织，保留可重复触发的冲突样本。
3. D-05～D-08 完成浏览、选择、元数据和组织视图。
4. D-09～D-11 完成媒体与 AI；3D/WebGL 单独标记环境限制。
5. D-12～D-14 完成撤回重做、回收站和资源库搬运；危险操作只到确认窗口。
6. D-15～D-16 完成设置、脚本、MCP、插件和权限模型。
7. D-17 完成错误、后台任务、完全退出/重启恢复。
8. D-18 做最终交付对账，并形成 E 阶段反馈清单。

## 通过口径

- “通过”：目标完整走完，结果可见，数据/范围/提示正确，至少一个后续动作证明状态已生效。
- “部分通过”：主路径完成，但有子能力失败或视觉/性能异常。
- “阻塞”：环境或权限使目标无法执行，例如无 WebGL、没有 Windows、没有可用 AI 端点；必须附证据。
- “失败”：产品行为与目标不符，立即记录复现步骤、截图、影响范围并生成工单。

## 输出物

- 一份按 D-01～D-18 的验收矩阵：目标、操作摘要、结果、截图、平台、问题工单。
- 一份人工发现反馈汇总，作为 E 阶段输入。
- 不在 D 阶段修改产品代码；修复统一留到 F，并对每个失败目标补自动化测试和 Luna 审查。
