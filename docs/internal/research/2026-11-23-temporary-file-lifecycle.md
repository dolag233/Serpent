# 临时文件生命周期审计

2026-11-23，静态检查桌面应用 Main、Library Worker、媒体预览及相关脚本。证据来自当前工作树的写入路径、清理路径和启动入口。未读取真实资源库，未启动 Electron，未模拟断电、磁盘满或文件占用。

## 先区分数据用途

- **持久库数据**：原始资产、数据库及其日志、恢复备份、回收站和操作恢复记录承担持久化或恢复责任。仅凭所在目录、大小或扩展名判断是否可删，会破坏这些功能。恢复流程中生成的临时副本也应先由记录它的流程判定是否可回收。[库服务和恢复流程](../../../src/worker/library-service.ts)
- **可重建缓存**：缩略图、波形、代理文件、持久化预览和本地预览镜像都是派生数据，但与正在读取的预览、数据库索引或 LRU 配额相关。明确清理时应走产物类型和所有权，而非递归按扩展名清理。FBX 转换命令把 GLB 登记成按源修订匹配的 `model_glb`，这解释了查看完后文件仍存在。把交互预览改成内存结果后，历史记录应通过 Worker 按类型回收。[FBX 转换及缓存](../../../src/worker/fbx/convert-command.ts) · [本地预览镜像](../../../src/main/preview-cache.ts)
- **任务临时数据**：上传、下载、解包、解码和原子替换的中间写入应有明确所有者，正常任务结束和异常恢复均有回收入口。小文件也应走相同的生命周期，避免通过列举全盘文件寻找残留。

外部资源库归档导入是可供复用的设计。它根据归档规模挑选有空间的暂存目标，登记暂存位置，并有启动回收，减少大文件无提示落到系统盘。开发脚本也会写本机临时目录，例如媒体二进制解压和基准测试，但这些入口不属于安装后日常运行的桌面功能。 [外部归档预检和回收](../../../src/main/external-library-archive.ts#L354) · [媒体依赖脚本](../../../scripts/media-binaries.mjs#L121) · [导航基准测试](../../../scripts/run-navigation-benchmark.mjs#L36)

验证后续修复时，用隔离目录分别测试写入失败、取消、进程异常退出后重新启动、多个实例之间的目录所有权，以及正在读取的临时文件。对大文件同时检查实际写入位置、峰值磁盘占用和任务结束后的目录。以上为静态审计结论，运行时行为、实际占用与各平台回收仍待验证。
