# 0014 — 资产选择与上下文操作

> 目标版本：v0.1.0
> 状态：backlog（需求已记录；右键菜单无法可靠关闭按 P0 缺陷先行修复）
> 建立日期：2026-07-14

## 背景

当前资产画布已支持单选、Shift 连续选择和 macOS Command / Windows Ctrl 增减选择，但缺少框选；多选后出现的顶部批量操作条会遮挡画布。资产、标签和合集的右键菜单也没有统一的布局、定位与关闭机制，存在点击外部后菜单仍不消失的问题。

本切片统一资产选择模型与上下文操作。复用 0012 的平铺/瀑布流画布和 0004/0007 的批量领域命令，不另造标签、合集、移动或删除语义。

## 选择模型

- 普通点击：只选择目标资产；点击画布空白处清空选择。
- Windows Ctrl / macOS Command + 点击：逐项加入或取消选择。
- Shift + 点击：从最近的选择锚点连续选择到目标。
- Ctrl/Command + Shift + 点击：把连续范围追加到现有选择。
- 从画布空白处拖拽显示选择框；相交规则必须固定并在平铺、瀑布流下保持一致。
- 框选接近画布上、下边缘时可自动滚动，松开后选择集合稳定。
- Esc 清空选择；视图切换、卡片尺寸缩放和连续加载不得因 DOM 重排丢失资产身份。
- Windows 的 Ctrl 组合必须在真实 Windows QA 中验证，不能用 macOS Command 结果代替。

## 上下文操作

- 移除当前遮挡画布的顶部批量操作条。
- 右击未选资产时先只选择该资产；右击已选资产时保留整个选择集合。
- 统一右键菜单显示“已选择 N 项”及适用于整个选择集合的标签、合集、移动、回收站、复制链接等动作；不适用的动作显示明确禁用原因。
- 同一时刻只允许一个上下文菜单存在。
- 菜单使用全屏 fixed backdrop 或等价可靠机制；点击菜单外部、Esc、滚动、窗口 resize、窗口失焦、切换范围及执行任意菜单项后都必须关闭。
- 菜单根据 viewport 自动 clamp/flip，四角打开不溢出；长标签/合集列表必须可滚动或分层呈现。
- 菜单需要与 Serpent 现有视觉语言一致，并具备明确焦点、键盘导航和可访问名称。

## UI 架构与视觉一致性

- 不再由资产、标签、合集、智能合集各自在 `App.tsx` 拼一套菜单 DOM；抽取统一的 `ContextMenu` / `ContextMenuItem` / `ContextMenuSection` 组件和单一状态控制器。
- 所有菜单复用同一组设计 token：背景与浮层边框、圆角、阴影、内外间距、行高、图标尺寸、分隔线、普通/悬停/聚焦/禁用/危险状态，以及最大高度与滚动条。
- 菜单项使用一致的“图标 + 动词 + 可选快捷键/状态”信息结构；破坏性动作单独分组，不以浏览器默认按钮样式混排。
- 定位、viewport clamp、焦点管理、关闭监听、动画和 portal 层级属于组件基础设施，业务菜单只提供语义项与处理函数。
- 后续 UI/UX 反馈优先修改共享组件与 token，并用资产、标签、合集、智能合集的截图矩阵防止只修一处、其余漂移。

## 优先级拆分

1. **P0 热修**：右键菜单点击外部/Esc/滚动后无法可靠消失、边缘溢出和多菜单并存。
2. **P1 完整切片**：框选、组合键模型、移除顶部批量条、统一批量右键菜单和视觉打磨。

## 验收条件

1. 平铺与瀑布流中均可框选；跨越当前可视区时自动滚动，首尾资产均可选中。
2. 普通点击、Shift、Ctrl/Command、Ctrl/Command+Shift、再次点击取消和 Esc 清选符合上述模型。
3. 多选不再出现顶部遮挡条；右键菜单对单项和整组操作的对象数准确。
4. 点击画布/侧栏、Esc、滚动、resize、窗口失焦后菜单都消失；四角打开不越界。
5. 标签、合集、移动和删除等批量操作只调用现有语义 API，成功数量、跳过数量及错误原因准确。
6. Electron E2E 覆盖两种视图、框选、组合键、菜单关闭与边缘定位；Computer Use 截图检查菜单视觉和遮挡；Windows 完成真实 Ctrl QA。
7. 资产、标签、合集和智能合集菜单均由同一共享组件渲染；截图矩阵中的圆角、阴影、间距、图标、危险动作与状态样式一致，不出现浏览器默认按钮外观。
