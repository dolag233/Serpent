## MVP 验收主线

导入或链接图片与视频 → 立即浏览 → 用文件夹/标签/元信息整理 → 关键词/过滤/排序找到目标 → 悬停预览/资产查看页面/显式全屏确认 → 外部应用打开。详见 `docs/product-brief.md`。

产品负责人真实使用后确认：功能存在不等于 MVP 可用，应用壳、目录浏览、文件操作、标签交互、双语和亮/暗主题均进入 v0.1.0。完整需求、开放决策和依赖见 `docs/implementation/mvp-ui-ux-requirements-backlog.md`。

暂定执行顺序：

1. 先修 0019 中阻断真实使用的 Inspector 缩略图、状态闪烁、组合键框选和瀑布流空当；

## 版本排期决定（2026-07-13）

- `v0.1.0`：完成产品简报既有 MVP，发布阻断范围为 0001–0010 及跨切片桌面主线。
- `v0.1.0` UX 收尾：0012 已完成；0013/0014 继续收口；真实使用新增的 0015–0019 同属 MVP，不推迟为发布后视觉打磨。结构性 UX 编码前必须完成竞品研究和交互原型，但已复现的 Inspector、选择和布局正确性缺陷不等待完整原型。
- `v0.2.0`：交付 0011 一等 CLI。该需求已经确认，不再回到探索状态；之所以排在 v0.2.0，
  是因为 CLI 横跨全部领域命令、跨进程写租约、持久变更序号和独立分发，必须建立在
  v0.1.0 已验收的领域语义之上。
- 这不是桌面客户端优先于 CLI；两个客户端仍是同等的一等入口。这里只表达实现依赖和版本风险。
