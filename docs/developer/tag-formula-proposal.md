# 标签逻辑公式（提案）

本页描述待讨论的参考实现；产品方向和最终语法尚未确认。

在现有搜索框输入显式前缀后，可以按完整标签名组合筛选：

```text
标签: (A | B) & C - D
tag-formula: (A | B) & C - D
```

两种写法都表示：具有 A 或 B，同时具有 C，并且不具有 D。人工标签和 AI 标签都参与匹配；当前资源范围与其他筛选仍然生效。

| 写法 | 含义 |
| --- | --- |
| `A & B` 或 `A B` | 同时具有 A、B |
| `A \| B` | 具有 A 或 B |
| `!A` 或 `-A` | 不具有 A |
| `(A \| B) & C` | 括号先计算 |
| `"科幻-角色"` | 双引号保留标签名中的空格或运算符 |

优先级从高到低为：非、与、或。双引号中的 `\"` 表示字面双引号，`\\` 表示反斜杠。标签使用数据库现有的大小写比较规则；不承诺完整 Unicode 大小写折叠。

普通文件名搜索、`tag:` 和 `tags:` 保持原有语义，包括 `tags:(A) name:hero`。公式入口进行完整标签匹配，因此 `A` 不会匹配 `AA`。公式后面的内容都属于标签公式；若需搜索名为 `name:hero` 的标签，建议加双引号明确表达。

未完成或非法公式会显示错误，不提交搜索。实现限制为 8192 个字符、64 层嵌套、单标签最多 512 字符，展开后最多 32 组，每组最多 32 个条件。复杂但逻辑正确的公式也可能被拒绝；这些上限是本提案的一部分。

实现复用共享查询模型，Worker 使用参数绑定；不新增数据库迁移。精确标签条件不依赖全文检索预筛选。参考测试见 `tests/unit/tag-formula.test.ts` 和 `tests/worker/tag-formula-search.test.ts`。
