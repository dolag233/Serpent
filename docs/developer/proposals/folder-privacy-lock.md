# 文件夹隐私锁提案

状态：需求与设计讨论，尚未实现。

## 目标与范围

为指定文件夹及其全部子目录提供密码解锁机制，避免未解锁时在 Serpent 内查看其中的素材。浏览器扩展遵循同一锁定状态，隐藏受保护目录及其后代。

本提案针对应用内隐私保护，原文件仍以现有方式存放；不承诺磁盘加密、操作系统权限隔离，或阻止旧版客户端、外部程序和拥有直接文件访问能力的插件读取原文件。

## 桌面端交互

- 文件夹菜单提供设置保护、解锁、立即锁定、修改密码和取消保护。修改密码、取消保护或将受保护内容移到未保护的位置，需要先解锁。
- 锁定覆盖整个目录树。桌面端可以保留受保护根目录的名称和锁图标，但不展示后代目录、素材数量或内容封面。
- 点击受保护目录时，在桌面端输入密码解锁；输入错误或取消时保持锁定，不展示内容。密码不明文持久化，解锁状态仅在当前会话有效。
- 搜索、全部素材、合集、最近浏览、标签结果、详情、缩略图、原图和预览遵循同一规则，不能从其他入口读取锁定内容。
- 立即锁定时关闭相关预览、终止未完成的内容读取，并使已打开页面和缓存失效。重启应用或重新打开资源库后恢复锁定。

## 浏览器扩展

- 锁定时，右键保存菜单、拖拽保存目录树、目录选择器和最近保存或浏览记录，都不显示受保护根目录及其后代，也不返回它们的名称、路径、计数或封面。
- 由桌面端的本机接口统一过滤目录与内容；扩展界面隐藏不能代替接口校验。通过旧目录 ID 访问或保存到锁定位置也应被拒绝。
- 桌面端重新锁定后，扩展及时清除相关缓存和最近使用项，更新已经打开的菜单。状态无法确认时不继续展示或使用缓存中的受保护目录。
- 已选择的保存目标在上传前变为锁定时，提示重新选择可用目录，不静默改存到其他位置。
- 解锁仅在桌面端完成，扩展不接收或保存密码。成功解锁后允许扩展重新获取目录；再次锁定时重新隐藏。
- 浏览器扩展属于独立仓库，后续实现需要协同约定状态通知、缓存失效及兼容策略；本提案不表示扩展现已支持该功能。

## 实现思路（待讨论）

- 在 Library Worker 的访问策略中统一判定目录及祖先的锁状态，主进程媒体出口、扩展本机接口及自动化入口遵循同一策略；不能只在 Renderer 折叠目录。
- 同时覆盖普通目录与链接目录。链接子目录是虚拟目录，需要考虑链接根与规范相对路径、重命名、移动及重新索引后的保护关系。
- 持久化锁配置和带随机盐的密码校验值，使用适当的密码派生函数；解锁会话只保存在内存，重新锁定时撤销访问。具体格式和参数在实现阶段评审。
- 锁配置独立于安装目录，采用兼容的数据迁移；升级后保留保护配置，默认处于锁定状态。旧客户端不理解此功能，应明确说明兼容边界。
- 当前浏览器扩展会保存最近使用的目录，需要在后续实现中处理历史缓存。对无法配合撤销展示的旧扩展，应在接口协商中明确处理，不能宣称已可靠隐藏。

## 后续实现的验收场景

以下是拟议的验收条件，不是本次已执行的测试：

1. 普通目录、嵌套目录和链接目录均能设置保护；错误密码、取消解锁、重启及重新开库时不能查看内容。
2. 锁定素材无法经搜索、合集、最近浏览、封面、缩略图、原图、媒体链接及自动化入口绕过访问限制。
3. 扩展的右键菜单、拖拽菜单、最近使用项及接口响应均隐藏锁定目录和后代；旧 ID 与旧缓存不能继续用于读取或保存。
4. 在预览、上传或扩展菜单打开期间重新锁定，相关内容和缓存被撤销，保存请求不会静默落到其他目录。
5. 修改密码、移出保护范围、重命名和移动目录时，保护关系按预期维护；未保护目录继续正常使用。
6. 应用升级后配置仍在，默认锁定；旧库正常打开，迁移与资源库可用性检查通过。

## 待维护者讨论
